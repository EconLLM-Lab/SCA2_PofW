The registration excludes this cut from the inference, because it conditions on the human criterion. Of the «n|SCR_absA_n_kept» items selected under the primary rule, «v|SCR_absA_n_kept|0» reach the cut. Their mean signed agreement is «v|SCR_absA_A_kept|3», and «pct|SCR_absA_share_pos_kept|1»§% of them have $a_i>0$, against «pct|SCR_share_a_pos|1»§% over all «n|SCR_share_a_pos» selected items. §section{The near-zero margin in full}§label{sec:s-nz}

The near-zero check refits two predeclared countries without the training pairs of every dimension whose GPS coordinate lies within §dc{0.10}{near_zero_cut} of zero, each beside a size-matched control trained on the same number of pairs drawn at random. For Great Britain (profile §texttt{P§_1§_1§_1§_1§_0§_1}) the rule removed altruism, negative reciprocity, positive reciprocity and risk taking, so trust and the two patience items stayed in training. For Colombia (profile §texttt{P§_1§_0§_0§_1§_1§_0}) it removed altruism, risk taking and trust. Table~§ref{tab:s-nz} gives every contrast. The predeclared reading uses only the retained imprint surfaces, which are Great Britain's trust and Colombia's positive reciprocity. The dropped dimensions are a loss-of-signal check: with no training pairs left on a dimension, its surface is expected to move away from its declared sign, so a move there bears on neither side.

The floor in the last column is the unseeded retrain's shift on the same surface (Table~§ref{tab:s-retrain}), and almost every contrast exceeds it. That floor comes from one retrain on the full training data, and it is too small for refits trained on a fraction of the data. The size-matched controls show why: a control differs from the full-data baseline by up to «v|NZ_GBR_max_abs_control_minus_baseline_sd|3» standard deviations for Great Britain and «v|NZ_COL_max_abs_control_minus_baseline_sd|3» for Colombia. Against that variation, neither retained imprint contrast stands out. We therefore claim no reversal, and the margin stays a footnote in the article.

§section{Provenance of the scoring runs}§label{sec:s-prov}

§paragraph{Specifications.} Each scoring condition has a pinned specification hash that fixes the prompt template, the option order, the leading space before each code and the recode. Every run reproduced its pin before a model was loaded. The strict battery's pin begins §texttt{ed3bb964b606}, and the amended held-out pool's pin begins §texttt{46447de63f7c}. The pre-amendment held-out pin, which Amendment~1 superseded, began §texttt{4d799b02}.

§paragraph{Code revisions.} All manifests of the held-out runs (the primary readout, the three readout variants and the prompted profiles) record the checkout revision §texttt{2126045}. During a recovery, three launcher files around that checkout were patched in place on the virtual machine to fix how a child environment was built. The scoring modules are byte-identical between the patched setup and the recorded revision, which the command §texttt{git diff --quiet 2126045 HEAD -- paper§_b/score§_runtime.py paper§_b/score§_plan.py paper§_b/score§_cohort.py} confirmed at the time. The strict-battery run of the second cohort spans two recorded revisions. All but three of its manifests record §texttt{5133387}, and the remaining three (profiles §texttt{P§_0§_1§_1§_1§_1§_1}, §texttt{P§_1§_1§_1§_1§_1§_0} and §texttt{P§_1§_1§_1§_1§_1§_1}) record §texttt{f34a79f}. The unseeded retrain and the strict scoring of the prompted profiles ran at §texttt{b2dbbfb}, and the near-zero refits at §texttt{d1ab226}. Between these revisions the readout path changed in four ways, none of which touches prompt construction, option parsing, the forward pass or the frozen readout constants. A unit-name resolution replaced upper-casing, and it is the identity for every country and profile unit. A check on the number of training pairs reads a per-unit expectation that equals §dc{526}{train_rows} for every unit outside the near-zero refits. Some functions gained annotations and parameters with backward-compatible defaults. The scoring loop gained a guard that stops with a named error when a scoring function is missing. The readout path is therefore not byte-identical across revisions, and what is verified is that every pin reproduces at the current revision and that the changes leave every scored unit's arithmetic unchanged.

§paragraph{The first-cohort scoring run.} The first cohort's scores (surface S1) were persisted by a run whose manifest records a digest of the code bundle rather than a git commit, and none of the tracked source snapshots matches that digest. The commit that produced the run therefore cannot be named. Two properties of the run were verified directly. Its specification hash, which fixes the prompts, equals the strict pin, and the weights of the one adapter checked match the archived manifest byte for byte. A later replay of five selected items on the base model and that adapter, using the same four-bit quantized base model, lands within three units of half-precision rounding of the stored option log probabilities, which is the precision at which they were stored. The same replay on the unquantized model departs by far more. Quantization is therefore the source of the dominant difference between the two configurations, and the stored first-cohort scores are consistent with the quantized model that the adapters were trained on. The full panel was not replayed.

§paragraph{The archive of the development stage.} Before every scoring run, a gate compared the base model's scores on the frozen software stack with the archived scores of the development stage, whose software environment was not pinned. The comparison is report-only by design. The formatted prompts matched the archive exactly, while the log probabilities differed by more than the tolerance used at the development stage. A replay with the same four-bit quantization moved the scores toward the archive without reproducing it, so the remaining cause of that gap is not established. The gap enters no statistic in the article, which uses only scores produced on the frozen stack.

§paragraph{The follow-up runs.} The adapters-plus-persona cell was scored in one run of the first-cohort adapters with the country-named persona prompt on the strict battery (run §texttt{adapter-persona-strict-v1-20261019}, pinned specification §texttt{persona§_strict§_v1}). Three gates passed before any country was scored: the fresh base model reproduced the banked strict base scores, one adapter without the persona prompt reproduced its banked first-cohort rows and differed from the base, and disabling the adapter returned the base. The held-out label recovery was scored in one run of the same adapters (run §texttt{label-recovery-cohort1-v1-20261019}), with the recipe that built the reference cache of the training pairs. Two gates passed before any country was scored: the base model reproduced the banked reference log probabilities on training pairs with a gap of zero, and one adapter changed the log probabilities while disabling it returned the base exactly. All country files were read back from the artifact store by hash. The code of both runs was written and run by the study team, and an independent audit of the two runs is pending.

§paragraph{Configuration.} The configuration file §texttt{paper§_b/config.py} serves both cohorts. Its first-cohort defaults are unchanged when the environment variable §texttt{SCA2§_PB§_UNITS} is unset, and the file is byte-identical to its version at the registration tag.

§paragraph{File hashes.} Hashes of text files are given for the working-tree bytes. The item pool §texttt{pool§_skeleton.csv} is written with Windows line endings by the pool-building script, while the repository stores text with Unix line endings, so the hash of the stored file differs from the hash of the file on disk. Both are given below. A reader who checks the freeze guard on a fresh checkout must regenerate the pool with §texttt{python paper§_b/heldout/build§_pool.py}, which reproduces the hashed bytes from the overrides file, because the guard compares raw bytes and refuses to run on the converted copy.
