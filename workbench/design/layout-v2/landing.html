Where does a language model's survey answer come from?

We ask a small language model a World Values Survey question, read its answer as a probability over the response codes, and then trace that probability back through every layer, attention head and neuron that produced it. Then we fine-tune the model toward one country's answers and measure, exactly, what moved.

1what a transformer computes

A running total, written to by many small parts

A transformer turns the prompt into tokens (word pieces) and gives each token a vector of 576 numbers. That vector is the residual stream: a running state that every layer reads and then adds to. Nothing overwrites it. This model has 30 layers.

Each layer adds two kinds of writes. Attention heads (9 per layer) move information between tokens: each head decides which earlier words to read from and writes a summary. The MLP (1,536 neurons per layer) then transforms each token on its own. After the last layer, the final state at the last position is turned into a score for every possible next token.

Because everything is added, the final score can be split into the parts that wrote it. That is the property the whole workbench rests on.

2what the workbench measures

One number, decomposed exactly

The answer (Eq. 6). At the last position the model scores every next token. We keep only the response codes and renormalise. That gives a choice probability over the answer options — the same object a survey researcher would model with a multinomial logit.

P(code j | prompt) = exp(zj) / Σk ∈ codes exp(zk) margin = zj₊ − zj₋

The decomposition (DLA). Direct logit attribution reads each part's write straight through the final layer. With the final normalisation scale held fixed, the margin is exactly the sum of an embedding term, 270 head terms and 46,080 neuron terms. Think of it as an accounting identity, like splitting a gap into components: every cell adds up, and nothing is left in a residual.

The checks. Every pass is run in float64 and must close: the residual stream must equal its parts to 1e-3, the attribution must sum to the margin to 1e-2, and our forward pass must agree with Hugging Face's reference implementation to 1e-10. If a check fails, the workbench shows it in red next to the readout.

Base vs fine-tune. The same prompt is run through two models: A (SmolLM2-135M-Instruct) and B (A plus a small LoRA adapter trained with DPO on USA survey answers). For every slice, the pair export stores the exact length ‖B − A‖ from both passes, and the size of the weight change.

What this does not show

Direct effect onlyDLA credits each part for what it writes straight to the answer. A head that changes what a later layer does gets no credit for that indirect path. Large DLA is not the same as “causes”; that needs ablation or patching.
A 135M stand-inSmolLM2-135M is a small model chosen so that every pass can be run in float64 and checked. The paper's models are larger. Patterns here are a method demonstration, not findings about those models.
Norms hide directionBlock heights are lengths of vectors. Two writes of equal length can point in unrelated directions; only the readout column (DLA) says which way a write pushes the answer.
Stored top-16 attentionAttention lines and prompt shading use the 16 largest weights per row; the stored mass says how much of the row they cover. One prompt per view; nothing here averages over items.
